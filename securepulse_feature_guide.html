#01✓ BUILT
REAL-TIME EVENT CORRELATION
Correlates security logs from multiple sources the moment they arrive — like joining puzzle pieces from different systems instantly.
HOW IT WORKS
Your agent on each server sends events (file changes, logins, process starts) to SecurePulse. The backend checks each event against all other recent events across all servers simultaneously. If a login attempt from IP X matches a file-change event 3 seconds later, it raises an alert.
REAL EXAMPLE FROM YOUR APP
failed_login × 6 from 198.51.100.42 at 2:08AM → correlated as brute-force → triggers isolation playbook automatically.
SEEN IN:Dashboard → Recent EventsAsset Detail → Event Log
#02✓ BUILT
SIEM INTEGRATION
Ability to ingest logs from external SIEM platforms like Splunk, QRadar, or Sentinel into SecurePulse.
HOW IT WORKS
SecurePulse exposes an API endpoint. External SIEMs forward their normalized logs to this endpoint. SecurePulse then processes them the same way as its own agent events — creating alerts, running detection rules, etc.
USE CASE
Your Splunk detects a suspicious AD login → forwards log to SecurePulse → SecurePulse creates incident automatically.

Every event arriving is tested against each active detection rule. Rules are evaluated in real-time. If an event matches a rule's condition (e.g., description contains "sudo"), a new alert is created at the defined severity level.

Learns what "normal" looks like for each user/host, then flags anomalies — not just known bad patterns.

The system builds a baseline of normal activity per user and host (typical login hours, usual commands, normal file access). When behaviour deviates significantly, it scores it and raises an alert — even if no explicit rule matches.
